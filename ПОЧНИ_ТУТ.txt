СВІТЛО ЧЕРКАСИ · v6.6 · ПІДГОТОВКА ДО ПУБЛІЧНОГО ЗАПУСКУ
===========================================================

ВАЖЛИВО: Це оновлення наявного проєкту, а не новий обліковий запис чи сервер.
НЕ змінюйте VAPID-ключі, ADMIN_PASSWORD, домен Railway та підписки.
НЕ видаляйте свій push-config.json: у архіві його немає спеціально.

ЩО ПОТРІБНО ЗРОБИТИ

1. Розпакуйте архів. Відкрийте папку svitlo-cherkasy-v6.6.
2. На GitHub відкрийте свій репозиторій svitlo-cherkasy.
3. Завантажте файли з цієї папки У КОРІНЬ існуючого репозиторію
   (не саму папку). Підтвердьте перезапис старих файлів, де потрібно.
   Особливо важливо завантажити приховану папку .github/workflows/.
   Додаткову внутрішню папку _site НЕ завантажуйте.
4. Перейдіть GitHub → Settings → Pages → Build and deployment → Source
   і виберіть «GitHub Actions» замість «Deploy from a branch».
   Це важливо: інакше дані автоматичного імпортера не обов'язково
   з'являтимуться на сайті після коміту з GITHUB_TOKEN.
5. GitHub → Actions → «Publish Svitlo Cherkasy PWA» → Run workflow.
   Дочекайтеся зеленого статусу та перевірте сайт.
6. GitHub → Settings → Actions → General → Workflow permissions:
   дозвольте «Read and write permissions», щоб імпортери оновлювали JSON.
7. На Railway → Deployments дочекайтеся нового деплою сервера
   з оновленого push-server. Якщо Root Directory сервісу = /push-server,
   це зазвичай стається автоматично після коміту.
8. Перевірте https://ВАШ-RAILWAY-ДОМЕН/health
   Параметри ok:true, lastPushCheck та pushCheckError допоможуть
   переконатися, що сервер працює й графік читається.
9. Відкрийте PWA з іконки на iPhone. Перевірте оновлення графіка,
   збережені адреси й налаштування Push. Адмінпанель — через /admin.html.
10. Протестуйте Push на своєму пристрої, а потім — ручну розсилку.

ЩО НЕ ТРЕБА РОБИТИ
- Не створюйте новий Railway-сервіс і не змінюйте порт.
- Не завантажуйте приватні VAPID-ключі у GitHub.
- Не надсилайте скриншоти з паролем або секретами.
- Не змінюйте користувачам черги без перевірки офіційного джерела.

ЩО ПОКРАЩЕНО
- Виправлено помилку в розрахунку стану світла між інтервалами.
- Усунено пропуски нагадувань через невеликі затримки серверного таймера.
- Одночасну відправку Push обмежено до 12 робіт, цикли не перекриваються.
- Події завершення екстрених обмежень не перекриваються старими активними.
- Швидша перевірка екстрених новин: за розкладом приблизно 15 хв
  (GitHub Actions може затримуватися; миттєву доставку не обіцяємо).
- Додано «Вимкнути Push і видалити підписку».
- При зміні VAPID ключа створюється нова правильна підписка.
- Попередження про застарілу перевірку джерела.
- Приватність і джерела даних описані окремими сторінками.
- Опубліковані дані автоматично запускають Pages Deploy, якщо змінилися.
- Збірка Pages публікує тільки публічні файли, виключає серверні скрипти.

ОБОВ'ЯЗКОВО ПЕРЕД ШИРОКИМ ЗАПУСКОМ
- Заповніть справжній контакт адміністратора в privacy.html і about.html.
- Перевірте дозволеність отримання/поширення відкритих даних оператора.
- Проведіть 1–2 дні реальної перевірки імпортера і Push на пристроях.
- Перевірте, що Railway не вичерпує ліміт і Volume зберігає підписки.
- Якщо використовуєте власний домен, після зміни APP_ORIGIN і
  SCHEDULE_URL перевстановіть PWA і повторно підпишіться на Push.

ЦЕ НЕ ОФІЦІЙНИЙ ЗАСТОСУНОК ЧЕРКАСИОБЛЕНЕРГО.
«Є світло/Немає світла» означає прогноз за графіком, не показник лічильника.
