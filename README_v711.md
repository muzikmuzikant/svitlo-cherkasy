# Світло Черкаси v7.1.1 — прогноз через опівніч, відсутній графік

## Правило, яке відповідає практиці оператора

- Якщо є **опублікований перевірений графік**, відображаються його інтервали.
- Якщо підтверджена публікація не містить конкретної підчерги, для неї після моменту публікації відключень не зазначено; попередній підтверджений графік не стирається частковою корекцією.
- Якщо після **успішної недавньої перевірки офіційного джерела** графіка на сьогодні або завтра немає, вважаємо, що планові відключення на цей день не оголошені. Інтервали доби відображаються зеленим.
- Якщо джерело недоступне, перевірка стара або є підозріла дата, відсутність публікації **не** перетворюється на обіцянку світла; показується невизначеність.
- Застосунок показує **планові графіки**, а не реальну напругу в будинку. Аварійні відключення можуть початися незалежно від графіка.

## Зручний конструктор графіків у адмінпанелі

У розділі **Дані та перевірки → Конструктор графіків** є сітка з 48 півгодинних комірок, перемикач дати й підчерги, перегляд інтервалів, кнопки копіювання та очищення. Це не обходить перевірку адміністратора: запис готується у `manual_overrides.json`, і лише потім публікується через існуючий GitHub API при наявності `GITHUB_TOKEN`/`GITHUB_REPOSITORY` на Railway. Якщо ці змінні не налаштовано, можна підготувати зміни, перевірити JSON і експортувати його для ручної публікації. Для внесення графіка потрібне достовірне посилання на офіційне джерело.

## Що зроблено

- Заголовок «Є світло до —:—» більше не використовується ні на головному екрані, ні на сторінці графіка.
- Наступну зміну шукаємо до кінця завтрашнього дня. Приклад: сьогодні 22:00, завтра перше відключення 05:00 => «Є світло до 05:00 завтра».
- Якщо зміни не заплановані, показуємо «За графіком світло є» з поясненням.
- Старий парсер раніше перетворював пропущені в першій щоденній публікації підчерги на «невідомо». Тепер після підтвердженої публікації вони вважаються без планових відключень, а часткові корекції не затирають попередні плани інших підчерг.
- Імпортер може позначати успішну перевірку стрічки новин навіть тоді, коли оператор не опублікував жодного графіка (за умови, що сторінка новин розпізнана). Зіпсована сторінка й збої завантаження не трактуються як день без відключень.
- Публікації з різкою невідповідністю дат позначаються як такі, що потребують перевірки; непідтверджені дні не фарбуються автоматично зеленим.
- Збережені адреси, підчерги, Push-підписки та іконка **не змінені**.

## Як оновити чинний GitHub Pages

1. Збережи резервну копію поточного репозиторію.
2. Розпакуй `svitlo-cherkasy-v7.1.1-update.zip`.
3. Завантаж усі файли зі збереженням структури папок у `muzikmuzikant/svitlo-cherkasy`, гілку `main`.
4. Натисни `Commit changes` і дочекайся зеленого `Publish Svitlo Cherkasy PWA` у GitHub Actions.
5. Перейди в `Actions -> Update official blackout data -> Run workflow`, один раз запусти перевірку імпортера. Якщо вона червона — перевір журнал; старі перевірені графіки не стираються.
6. У встановленому PWA: `Опції -> Перевірити оновлення застосунку`.
7. Перевір приклад без графіка на завтра і приклад із завтрашнім графіком. Нова редакція не вимагає перевстановлення PWA.

**Не потрібно змінювати Railway, домен, APP_ORIGIN, VAPID-ключі, Push-конфігурацію чи DNS.** Для опублікування змін з конструктора через GitHub потрібне налаштування GitHub-токена на Railway, якщо його ще немає. Зберігайте секретний токен лише в Railway Variables.

## Межі перевірки

Локально пройдено тести парсера, дат, переходів через опівніч, неповних графіків і збоїв джерела. Не перевірено фізичну наявність електрики і не виконано розгортання у твоєму GitHub.
