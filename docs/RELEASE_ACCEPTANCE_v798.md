- Production Railway: project `exciting-delight`, сервіс `svitlo-cherkasy`, окремий том `svitlo-cherkasy-volume` на `/data`, регіон `europe-west4-drams3a`.

- `main` має власні оновлення `data/schedules.json`, `data/emergency.json`, `data/source_review.json` та `google651cc9e5e29fd428.html`. Вони збережені.
- Production `CNAME`, `push-config.json`, `robots.txt` та `manifest.webmanifest` залишені з `main`; налаштування Beta у Production не переносилися.
- Реклама за замовчуванням вимкнена на новому бекенді, доки не затверджено відповідальну особу, контакти та правові підстави.

## Безпечна послідовність фактичного випуску

1. Створити точку відновлення даних Railway і переконатися, що її можна знайти у Backups.
2. Не вимикати Production cron. Не переносити Beta volume, Beta VAPID, Beta manifest ID, GitHub proof, `data/*`.
3. Виконати ручні Push/iOS/admin перевірки та погодити юридичні тексти.
4. Після зелених check runs і завершених блокерів злити PR із зафіксованим SHA; GitHub Pages і Railway можуть оновитися автоматично. Не перемикати source вручну.
5. Перевірити `/health`, графіки, адмінку, повідомлення та оновлення Service Worker. Якщо відмовляє код, повернути попередній commit/деплой, не відновлюючи том зі старими даними без окремої перевірки.
