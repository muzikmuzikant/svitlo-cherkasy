## P0. Те, що не можна втратити
- [ ] Пакет `AGENTS.md` та `docs/AI_*.md` доступний у GitHub і містить останній коректний статус, посилання на старі правила, відомі проблеми й покрокові інструкції.
- [ ] Документацію прийнято окремим PR у `staging`. **Не здійснювати push або merge у `main` без прямого дозволу власника.**
- [ ] Перевірено, що власник має власний GitHub доступ до репозиторію, Cloudflare, Railway, NIC.UA/DNS і пов'язаних облікових записів. Перевіряти доступ самостійно в налаштуваннях кожного сервісу, не надсилати нікому паролі або recovery-коди.
- [ ] Збережено резервну копію коду **обох** гілок `main` та `staging` на iCloud Drive/комп'ютер (GitHub → Code → Download ZIP після вибору потрібної гілки); збережено дату та commit кожного архіву.
- [ ] Окремо перевірено **бекап реального Railway volume**: Push-підписки, звернення, адмінконтент, історія, налаштування. Один GitHub ZIP не містить цих живих даних. Не експортувати приватні дані в публічні репозиторії та не ділитися ними з ШІ.
- [ ] Перевірено Railway billing/trial і прогнози витрат; визначено, як підтримувати production після trial. Не допускати тихого припинення серверних Push і повідомлень.
- [ ] Перевірено актуальність домену/DNS і можливість відновлення розгортання без зміни VAPID та адреси сайту.
- [ ] Зафіксовано, що beta і production ізольовані; бета ніколи не має працювати з production volume чи масовими Push.

## 24 жовтня. Надійність і перевірка
- [ ] **Push**: перевірити одне тестове нагадування про швидке вимкнення і одне про відновлення на власній тестовій підписці, коли PWA закрито; логувати спробу, server accept, iPhone receipt. Масових повідомлень НЕ робити.
- [ ] Перевірити дедуплікацію: **одна подія = одне сповіщення**, повторний polling/перезапуск не дублює відправку; після публікації нового графіка не губиться нагадування.
- [ ] Перевірити завантаження планових даних після міграції schedule worker на Railway: час, джерело, помилки, freshness, резервація; безпечний fallback.
- [ ] Звірити мінімум показові адреси, у тому числі проблемні звернення щодо 1.1 та Слободи; правильність підчерг і змін назв.
- [ ] Перевірити підтримку у двох сесіях: нове повідомлення і зміна статусу з'являються без перезавантаження; видалене звернення не залишається через старий кеш.
- [ ] Повторити `Installed PWA cold offline boot`, спершу полагодивши установлення браузера у workflow; ручний сценарій перевірити окремо.
- [ ] Перевірити теми, анімації шторок і кліків, відсутність горизонтального скролу / випадкового zoom на iPhone, beta offline/online.
- [ ] Пройти секретність і доступ до приватних фото/відео у зверненнях: авторизація, відсутність публічних посилань, видалення, retention.

## Необов'язкове після 25 жовтня
- Розширення АСКОД-подібної адмінки, поглиблена аналітика, рекламна система лише за окремою згодою, нові соціальні канали, UI polish поза критичними regressions, додаткові райони.
- Це **не** повинно відсувати перевірку реального графіка, Push, звернень, безпеки та фінансування хостингу.

## Що робити з iPhone, коли Plus завершиться
1. Не видаляй основний ChatGPT акаунт, історію чи GitHub репозиторій. Безкоштовний ChatGPT залишається можливим, але має інші ліміти.
2. Відкрий GitHub `muzikmuzikant/svitlo-cherkasy`, вкажи гілку `staging`, відкрий `AGENTS.md` і файли з `docs/`. За потреби передай новому асистенту посилання на репо й текст відповідних документів.
3. Якщо наступний ШІ має доступ до GitHub, дозволь йому **спершу читати** репозиторій, а потім робити зміни в окремій гілці. Перевіряй коміти та PR; `main` не чіпати.
4. Коли доступ до GitHub через ШІ недоступний, користуйся GitHub Mobile/Safari для перегляду PR і готуй точкові патчі з ChatGPT Free. Не копіюй туди приватні дані користувачів, серверні секрети та ключі.
