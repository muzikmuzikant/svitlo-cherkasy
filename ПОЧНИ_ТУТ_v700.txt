СВІТЛО ЧЕРКАСИ v7.0.0 — ОНОВЛЕННЯ ДОПОМОГИ Й АДМІНПАНЕЛІ

ВАЖЛИВО: сайт переходить на HTTPS-домен svitlo-cherkasy.pp.ua. Якщо GitHub ще створює TLS-сертифікат, спочатку дочекайтеся його готовності. Для Push і звернень застосунок має працювати через https://. Це оновлення НЕ виправляє сертифікат.

1. ЗРОБІТЬ РЕЗЕРВНУ КОПІЮ свого GitHub-репозиторію перед оновленням.
2. Візьміть svitlo-cherkasy-v7.0.0-update.zip; розпакуйте архів. Це архів лише змінених і нових файлів, він не містить секретів, не перезаписує ваші графіки data/schedules.json, адресні бази, push-config.json або CNAME.
3. Завантажте розпаковані файли в КОРІНЬ репозиторію, зберігаючи папки scripts/, push-server/, tests/, .github/ та data/. У папці data/ тільки НОВИЙ файл source_review.json. На GitHub використовуйте Add file → Upload files → Commit changes. ZIP напряму у репозиторій не завантажуйте.
4. Відкрийте GitHub → Settings → Pages → Source → GitHub Actions. У вкладці Actions перевірте зелений статус Publish Svitlo Cherkasy PWA. Якщо треба — запустіть workflow вручну.
5. Railway → ваш Push-сервер → Settings → Source: гілка main, Root Directory /push-server. Переконайтеся, що було створено нове розгортання з версією 7.0.0. Не запускайте старий Redeploy, який використовує старий код.
6. Railway → Variables: APP_ORIGIN = https://svitlo-cherkasy.pp.ua (ЖОДНОГО слеша в кінці), SCHEDULE_URL = https://svitlo-cherkasy.pp.ua/data/schedules.json. APP_ORIGINS не потрібен, якщо немає другого домену. Збережіть чинні ADMIN_PASSWORD, VAPID_PUBLIC_KEY, PUSH_PRIVATE_KEY, PUSH_CONTACT, DATA_FILE. Volume має залишатися змонтованим. DATA_FILE рекомендується /data/subscribers.json.
7. Перевірка Railway: відкрити https://ВАШ-ДОМЕН-RAILWAY/health; очікується ok:true. У логах має бути svitlo-cherkasy-push@7.0.0 start. Без SSL на домені джерело даних може бути недоступним, але сервер має запускатися.
8. Відкрийте https://svitlo-cherkasy.pp.ua/admin.html після готовності HTTPS. Увійдіть із ADMIN_PASSWORD із Railway. Нові вкладки: Огляд, Дані та перевірки, Звернення, Push, Центр допомоги, Редактор, Журнал.
9. Перевірте нову сторінку https://svitlo-cherkasy.pp.ua/help.html. FAQ доступний навіть при тимчасовій недоступності сервера; редаговані адміністратором статті підтягуються через Railway за наявності зв’язку. Для перевірки статусу звернення потрібен його номер SC-XXXXXXXXXX. Текст та email не показуються.
10. Натисніть «Оновити» в адмінпанелі, подивіться результати перевірки джерел. Після наступного планового запуску імпортера підозрілі розбіжності дат будуть записані в data/source_review.json і з’являться в адміністративній вкладці «Дані та перевірки». Попередній підтверджений графік НЕ стирається.

ПРО БЕЗПЕКУ ДАТ:
Якщо в офіційній публікації заголовок «8 липня», а реальна дата публікації 8 жовтня, імпортер відхиляє цей графік (різниця понад три дні), записує причину до журналу перевірок та не замінює ним попередній. Це консервативне правило: рідкісні реальні коригування старих графіків також можуть вимагати ручної перевірки. Графіки є прогнозом, не фактичною наявністю світла.
