# v7.0.0 — Центр допомоги, адмінпанель, контроль дат

Детальна інструкція у `ПОЧНИ_ТУТ_v700.txt`. Версія 7.0.0 створена на основі повної v6.9.2, без заміни адресного довідника та вже налаштованих секретів.

## Реалізовано

- Консервативна перевірка дати заголовка новини і часу її публікації. Розбіжності понад 3 доби потрапляють до `data/source_review.json`; графік не застосовується автоматично.
- Окремі вкладки адмінпанелі: огляд та стан джерел; виявлені помилки дат; звернення з пошуком, статусами та експортом; ручні Push; редагування довідкових статей й оголошень; редактор офіційних даних; журнал дій.
- Центр допомоги `help.html` зі швидким пошуком, категоріями, відповіями навіть офлайн, посиланнями на форму звернень та перевіркою статусу звернення за номером без доступу до приватного вмісту.
- Статті адміністратора зберігаються лише в `/data/help-content.json` (або поруч із DATA_FILE); журнал — в `/data/admin-audit.json`.
- Доопрацьовано світлий стиль, підтримку маленьких екранів і зниженої анімації.

## Обмеження

Це кодовий реліз, не підтверджений бойовий деплой. GitHub Pages потребує чинного TLS-сертифіката для PWA/Push. Не можна гарантувати миттєвих екстрених Push за затримок публікацій або GitHub Actions. Діагностика не замінює офіційного підтвердження графіків.

# Світло Черкаси · v6.5 — встановлення PWA + справжній вхід в адмінпанель

## Що змінилось

- У звичайному Safari / Chrome / браузері на ПК видно **лише сторінку встановлення** з інструкціями для конкретної платформи. Графіки і форма адрес **не запускаються** у звичайній вкладці.
- Із **встановленої іконки** (`display-mode: standalone` або `navigator.standalone` в iOS) відкривається той самий повний застосунок із адресами, графіками та Push.
- Адмінпанель `admin.html` доступна у браузері, але до входу її робочі інструменти приховані. Вхід — **тільки пароль**; адресу Railway зазвичай автоматично береться з вашого існуючого `push-config.json` (ручне поле в деталях, якщо потрібно).
- Сервер приймає пароль тільки на `POST /api/admin/login`, видає випадковий тимчасовий токен (12 годин), який використовується для запитів. Вихід `POST /api/admin/logout` одразу анулює токен. Після перезапуску Railway доведеться увійти повторно.
- Фонові Push, власні повідомлення, вибір підчерги та експорт/редагування графіків залишені. `GITHUB_TOKEN` потрібен лише для публікації файлів, а не для розсилки Push.

### Встановлення поверх v6.4 (рекомендовано)

1. Візьміть **мініархів `svitlo-cherkasy-v6.5-update.zip`**. Завантажте змінені файли в ті ж папки GitHub, підтвердіть заміну, зробіть Commit.
2. **Не видаляйте і не змінюйте `push-config.json`**: він уже містить вашу адресу Railway і публічний VAPID-ключ. Мініархів його не містить.
3. Дочекайтеся GitHub Pages; Railway має розгорнути новий `push-server/admin.js` автоматично (якщо підключений до того ж GitHub). Перевірте `Active` у Railway → Deployments.
4. `ADMIN_PASSWORD` у Railway потрібен, як і раніше; пароль та VAPID-ключі знову створювати не потрібно. Відкрийте `https://muzikmuzikant.github.io/svitlo-cherkasy/admin.html`, увійдіть **паролем**, потім керуйте Push і графіками.
5. Відкрийте головну адресу сайту у звичайному браузері → побачите тільки інструкції. Для перевірки повної функціональності закрийте браузер і відкрийте «Світло Черкаси» з іконки встановленого PWA. Після зміни Service Worker іноді потрібне повторне відкриття чи очищення кешу.

**Обмеження:** вебсайт на GitHub Pages лишається публічним і його JS/JSON доступні досвідченим користувачам. Режим «тільки з іконки» — **керування інтерфейсом**, не захист даних і не DRM. Серверні адміндії справді захищені перевіркою токена та пароля на Railway.

> Якщо користуєтеся повним ZIP замість мініоновлення, НЕ видаляйте робочий `push-config.json` на GitHub і не скидайте Railway Variables.

# Світло Черкаси v6.4 — ручні Push, тестові Push та адмінпанель

Неофіційний застосунок для Черкас та населених пунктів району. **Не є сервісом АТ «Черкасиобленерго» чи «Київ Цифровий».** Статуси «Є світло / Немає світла» — **за опублікованим ГПВ, а не перевірка напруги в оселі**.


## Нове у v6.3

- **Слобода:** вбудований довідник офіційно опублікованих вулиць і провулків, зокрема тих, для яких оператор не вказує номерів будинків. Пошук дає можливі підчерги без номера, але ніколи не називає їх підтвердженим визначенням конкретного будинку. Довідник доповнюється успішним PDF-імпортом.
- **Годинні таблетки:** замість одного синього напису на змішаних годинах — два взаємно замасковані шари: чорний текст зі звичайною блискавкою на світлій частині, білий текст із перекресленою блискавкою на темній. Кожна хвилина враховується точно. Клітинка 19:00–20:00 при початку відключення о 19:30 світла зліва й темна справа.
- **Екстрені / аварійні:** консервативний імпортер новин оператора шукає чітко датовані офіційні повідомлення. Новина не доводить, що саме ваш будинок знеструмлений. Сповіщення для свіжої публікації можуть надходити при відкритому PWA; на заблокованому iPhone потрібен підключений сервер.
- **Адмінпанель `admin.html`:** статистика, перегляд та перевірка JSON, пошук вулиці, швидкі дії для підчерги/графіка/повідомлення, експорт. Реальна публікація в GitHub захищена серверною перевіркою пароля й токеном із правом запису в репозиторій. Зміни за можливості робіть через `data/manual_overrides.json`, щоб їх не стер плановий імпортер.
- **Сповіщення:** окремий перемикач екстрених повідомлень; push-сервер надсилає їх лише при чітко активному офіційному оголошенні (не пізніше 65 хв після публікації). Точність доставки залежить від мережі, iOS та хостингу.

**Критично:** початкова `data/addresses.json` порожня, поки GitHub Actions не відпрацює з живими PDF. Статичний довідник Слободи дозволяє вибрати можливі підчерги, але сам по собі не встановлює чергу будинку. Ні екстрений стан мережі, ні фактична напруга в конкретному будинку цим застосунком не вимірюються.

## Нове у v6.4 — тестовий Push і ручні сповіщення

У `admin.html` є розділ **Push-повідомлення**: тест на цей пристрій / всі зареєстровані телефони; власний заголовок і текст; вибір аудиторії (усі або підчерга); попередній перегляд; підтвердження перед масовим надсиланням. Нові API з паролем доступні через вже існуючий Railway-сервер, без GitHub-токена. Для роботи оновіть файли й Railway-деплой та додайте серверну змінну `ADMIN_PASSWORD`. Налаштовані VAPID-ключі та домен змінювати **не потрібно**. Покрокова інструкція — `push-server/README.md` (на самому початку).

## Що є у v6

- Тільки світла тема; адаптивний iPhone-подібний дизайн, переходи між 4 розділами, анімації карток, статусів, кнопок та форм; підтримка `prefers-reduced-motion`.
- Усунені типові мобільні баги: поля 16 px для Safari, viewport-fit, `overflow-x:clip`, блокування фонового прокручування й відновлення позиції після закриття форми; скролбар не показується.
- Статус **«Є світло до: HH:MM» / «Немає світла до: HH:MM»** з поточним відліком; якщо графіка немає, час **не вигадується**.
- Компактна добова шкала, повний погодинний графік, дні тижня, окрема візуальна іконка блискавки, підсумок годин.
- Додавання кількох адрес з власними назвами; вибір основної адреси; сортування у списку вибору адрес (стрілками на мобільному, перетягуванням на ПК).
- Автопідказки вулиць, нормалізація назв, **автоматичне визначення підчерги тільки при однозначному точному збігу будинку в підтвердженій базі**. Неоднозначні адреси → ручний вибір та перехід на офіційний сайт зі скопійованою адресою.
- Підтримка населених пунктів Черкаського району: парсер розпізнає справжню назву районної секції **«ВСП Черкаські ЕМ»**, сільські назви всередині рядків PDF та окремі списки вулиць. Перейменовані населені пункти нормалізуються за постановою №3984-IX (Червона Слобода → Слобода, Первомайське → Соснове, Іванівка → Яничі). **Далеко не всі адреси можна автоматично визначити** — офіційні переліки часто описують цілі вулиці, а не точні будинки.
- Парсер часткових графіків (не вимагає, щоб були всі 12 підчерг), збереження редакцій у межах дня, джерело кожного розкладу, історія підтверджених змін.
- Офлайн-кеш останніх успішно отриманих даних; автоматична перевірка при відкритому PWA кожні 5 хв.
- Сповіщення перед відключенням (30 хв), перед запланованим відновленням (15 хв), про зміни графіка та публікацію на завтра. **Без окремого push-сервера ці нагадування спрацьовують тільки коли застосунок відкритий** (і браузер дозволяє показ повідомлень). Для повідомлень на заблокований iPhone додано готовий окремий Node.js Web Push модуль `push-server/`, який треба самостійно розгорнути на HTTPS із постійним диском (дивіться `push-server/README.md`).

## Виправлення v6.1 (10 жовтня 2026)

**Півгодини.** Раніше змішана годинна клітинка малювала темну частину завжди зліва незалежно від того, коли починалось відключення. Новий `hour-paint.js` проходить по кожній хвилині й малює стани **в хронологічному порядку**: `19:00–19:30` зелений, `19:30–20:00` темний, якщо відключення почалося о 19:30. Відновлення о 19:30 працює у зворотному напрямі. Також підтримуються інтервали не кратні 30 хвилинам.

**Села.** Попередня версія неправильно розпізнавала назву районної філії, вимагала, щоб назва села стояла в окремому рядку, та містила помилку відступів, що втрачала всі підказки вулиць, крім останньої. Виправлено всі три причини. Якщо перелік згадує лише вулицю без будинку, застосунок пропонує **кандидат підчерги за вулицею**, але не стверджує, що це перевірена адреса. Для точного автоматичного підтвердження потрібен номер будинку в офіційному переліку.

**Важливо:** у ZIP немає вигаданих черг для сіл. Файл `data/addresses.json` має заповнитися **після запуску GitHub Actions**. У логах кроку `Show import summary` видно кількість імпортованих сіл і адрес. Якщо їх нуль — імпорт ще не працює і потрібно перевірити логи. У поточному середовищі всі 12 живих PDF завантажити не вдалося, тому повне покриття адрес не підтверджене; перевірялися структура офіційного PDF 1.1 та тести з реальною структурою тексту.

**Перевірка:** `python -m pytest -q tests`, `node tests/test_hour_paint.cjs`, за потреби `python tests/mobile_smoke.py` (потрібні Playwright і Chromium).

## Швидка публікація на GitHub Pages (рекомендовано)

1. Розпакуйте ZIP. Усередині одна папка **`svitlo-cherkasy-v6`**. Публікуйте **вміст цієї папки**, а не саму папку (інакше `index.html` не буде в корені репозиторію).
2. На https://github.com/new створіть **Public** репозиторій, наприклад `svitlo-cherkasy`.
3. Додайте файли **в корінь** репозиторію. У тому числі приховану папку `.github/workflows/update.yml` (якщо вебзавантаження її пропускає: Create new file → ім’я `.github/workflows/update.yml` → вставте вміст цього файлу). **Не публікуйте** приватні VAPID ключі та файл `push-server/subscribers.json`.
4. `Settings → Pages → Build and deployment → Deploy from a branch → main → / (root) → Save`.
5. `Settings → Actions → General → Workflow permissions → Read and write permissions → Save`.
6. Відкрийте вкладку **Actions → Update official blackout data → Run workflow**. Дочекайтеся завершення. **Зелений статус — імпортер запустився успішно.** Перевірте оновлені дати у `data/schedules.json` і кількість ключів у `data/addresses.json`; імпорт адрес може не вдатися незалежно від імпорту графіків (у логах це видно).
7. Сайт: `https://ВАШ-ЛОГІН.github.io/svitlo-cherkasy/`. Відкрийте на iPhone у Safari → Поділитися → **На початковий екран**.
8. GitHub Actions намагатиметься отримати нові графіки приблизно **двічі на годину**. У GitHub бувають затримки запуску; гарантій хвилина-в-хвилину немає. Файл із даними оновлюється окремими комітами. При помилці парсингу старі дані не стираються.

### Якщо GitHub не дозволяє більше ніж 100 файлів

У папці проєкту небагато файлів. Не завантажуйте `__pycache__`, `.pytest_cache`, `node_modules`, локальні `.env`, `subscribers.json` та інші допоміжні директорії. Якщо використовуєте вебінтерфейс, завантажуйте `index.html`, CSS/JS, `assets/`, `data/`, `scripts/` і `.github/workflows/`.

## Локальний запуск на Windows

1. У Проводнику відкрийте папку `svitlo-cherkasy-v6`.
2. У адресному рядку Проводника наберіть `cmd` → Enter.
3. Введіть:

   ```cmd
   python -m pip install -r requirements.txt
   python local_server.py
   ```

4. Відкрийте **http://localhost:8000**.
5. Для зупинки натисніть `Ctrl + C`. Якщо команда `python` не працює, використайте `py`.

`python -m http.server 8000` показує інтерфейс, але **не запускає** автоматичний імпортер. Для локального збору графіків треба запускати саме `local_server.py`.

## Як працюють офіційні дані

- `scripts/update_data.py --schedules-only`: читає офіційну стрічку новин, знаходить графіки, перевіряє дати/підчерги/інтервали, складає останні редакції й зберігає `data/schedules.json`. Якщо конкретна підчерга **відсутня** в публікації й немає попереднього графіка, її стан **невідомий**, а не «зі світлом».
- `scripts/update_data.py --addresses-only`: читає перелік PDF черг 1.1–6.2, пробує обробити секції «Черкаські міські ЕМ» і «Черкаські районні ЕМ» та виписати точні номери будинків. Адреси без номера, діапазони без точних переліків та неоднозначні варіанти не позначаються як точні збіги. Підказки за цілою вулицею використовуються лише для ручної перевірки.
- Сторінка адрес оператора: https://www.cherkasyoblenergo.com/off. **Підстановку значень у форму зовнішнього сайту не гарантовано**, тому PWA відкриває офіційний сайт і намагається скопіювати введену адресу у буфер обміну.
- **При першому завантаженні `data/addresses.json` порожній:** автоматичний пошук за точним будинком стане доступним тільки після успішного імпорту 12 документів. Ця вимога захищає від хибного визначення черги, але може тимчасово змушувати вибирати її вручну.

## Офлайн і Web Push

- `sw.js`: кешує оболонку застосунку та останні успішні JSON-файли. Для першого офлайн-перегляду треба хоча б раз відкрити сайт онлайн.
- Для **сповіщень на заблокований iPhone** потрібні Web Push і окремий онлайн-сервер. Встановлені на головний екран PWA підтримують Web Push починаючи з iOS 16.4. Встановіть і налаштуйте `push-server` за його README, тоді заповніть `push-config.json` у корені PWA. **До цього системні фонові Push не працюють**.
- Фонові push повідомлення не гарантують точного часу: доставка залежить від провайдера, зв'язку й режимів iOS.

## Адмінпанель, екстрені події та сервер

- `admin.html` — панель діагностики, перевірки, JSON-редагування і зручних дій без необхідності переписувати весь файл.
- `push-server/admin.js` — приватний шлюз до GitHub Contents API для запису через HTTPS із перевіркою `ADMIN_PASSWORD`, `GITHUB_TOKEN`, `GITHUB_REPOSITORY`.
- `data/manual_overrides.json` — ручні уточнення, що не перезаписуються імпортером. Якщо виправляєте графік, обов’язково залишайте офіційне джерело.
- `data/emergency.json` — датовані повідомлення оператора, що підтягнуті з новин. Активність визначається за чіткими формулюваннями, а не довільним припущенням; повного покриття всіх аварій без офіційного API не гарантовано.
- Для ввімкнення серверної адмінпанелі та справжніх Push дивіться **`push-server/README.md`**. Відсутність окремого сервера означає, що **немає захищеної серверної адмінпанелі та фонового Push**.

## Оновлення встановленого PWA (v6.7+)

Користувачам НЕ потрібно перевстановлювати застосунок при наступних релізах, якщо домен не змінюється.

- При відкритті PWA браузер сам перевіряє новий Service Worker і завантажує нові HTML/JS/CSS.
- Якщо PWA залишається відкритим, файл `release.json` перевіряється приблизно раз на 15 хвилин, при поверненні в застосунок або вручну: Опції → Перевірити оновлення застосунку.
- Якщо з'явився новий реліз, користувач бачить банер і кнопку «Оновити». Перезавантаження не видаляє адреси, підчерги, налаштування або Push-підписки.
- Для КОЖНОГО нового релізу змінюй `version` у `release.json` (x.y.z) та опис релізу. `scripts/build_pages.py` автоматично підставить номер у зібрані HTML і Service Worker. Не потрібно змінювати версію в різних файлах вручну.
- Оновлення файлів `data/*.json` не потребує збільшення версії програми — застосунок уже завантажує їх окремо.
- Щоб повідомити про реліз користувачів навіть без відкриття PWA, після публікації можна зробити ОДНУ ручну Push-розсилку з адмінпанелі. Жодна автоматична розсилка про реліз без окремого налаштування не запускається.
- ВАЖЛИВО: якщо сайт переходить з `muzikmuzikant.github.io` на `svitlo-cherkasy.pp.ua`, через зміну origin потрібне одноразове встановлення з НОВОГО домену та повторна підписка на Push. Після такого перенесення подальші релізи оновлюються без повторних встановлень.
- Перевіряти PWA слід через HTTPS у standalone mode, оскільки звичайна вкладка навмисно показує лише екран встановлення.
