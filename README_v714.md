# Світло Черкаси v7.1.4 — часті виправлення графіків

## Головні правила

- Якщо в останній підтвердженій публікації на день немає певної підчерги, для неї **не заплановано** відключень на весь день. Старі години цієї підчерги не переносяться з попередньої редакції.
- Якщо на день взагалі не було публікації та перевірка **успішна й свіжа**, усі підчерги вважаються вільними від **планових** відключень. Це не показник реальної наявності електроенергії й не скасовує аварійні повідомлення.
- Збій завантаження/розпізнавання не перетворюється на "весь день зі світлом".

## Автоматична синхронізація

- `.github/workflows/update.yml`: перевірка **кожні 5 хвилин цілодобово** (cron `2-57/5 * * * *`, у часовому поясі UTC). GitHub Actions може затримати або пропустити запуск.
- Якщо змінився **зміст інтервалів** у тій самій новині з тим самим часом публікації, імпортер визначає нову редакцію за `planFingerprint`, зберігає `detectedAt` і `revisionId` в історії змін. Це дає змогу коректно обробити багато редагувань протягом години.
- Якщо змінилися години або статус достовірності — GitHub негайно фіксує файл і надсилає подію для Pages. Без змін час успішної перевірки публікується приблизно кожні 30 хвилин, щоб не перевантажувати Pages.
- Push-сервер (Railway) використовує час виявлення (`detectedAt`), а не старий час новини, для визначення свіжості редакції. Дедуплікація за `revisionId` не губить кілька редакцій з однаковим часом публікації.
- Сайт читає свіжий JSON із `cache: no-store` при відкритті, поверненні до PWA й періодично (у відкритому застосунку — кожні 5 хвилин).

## Встановлення поверх v7.1.1–v7.1.3

1. Зробіть резервну копію GitHub репозиторію (Code → Download ZIP).
2. Завантажте в репозиторій **усі файли** архіву `svitlo-cherkasy-v7.1.4-update.zip` зі збереженням папок і назв, особливо `.github/workflows/`, `scripts/` і `push-server/server.js`. Застосунок, сертифікат, іконки та користувацькі налаштування залишаються без змін.
3. Зачекайте завершення GitHub Actions `Publish Svitlo Cherkasy PWA`.
4. Запустіть вручну `Actions → Update official blackout data → Run workflow`, перевірте, що не було помилки імпортера; після успішної публікації перевірте `data/schedules.json` і календар застосунку.
5. Якщо Railway автоматично деплоїться з підключеного GitHub-репозиторію, оновлений Push-сервер підхопиться після його деплою. Ключі VAPID, пароль адмінки, `APP_ORIGIN`, `SCHEDULE_URL` і домен не змінювати.

**Update ZIP не містить `data/`, `CNAME`, `push-config.json` або секретів.** Дані графіків не переписуються — тільки механізми їхнього отримання.

## Перевірки

- `python -m pytest -q tests`
- `node --test tests/*.cjs tests/*.mjs`
- `python scripts/build_pages.py`

Тести з імітованим офіційним HTML підтверджують: графік для 1 із 12 підчерг, повну відсутність графіка, відкат до невідомого стану при недоступному джерелі, три редакції **тієї самої** новини з незмінним часом публікації та недублювання подій. Справжнє завантаження після деплою потрібно перевірити в GitHub Actions.
